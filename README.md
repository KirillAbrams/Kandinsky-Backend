# Сервер Кандинского

Сервер хранит чаты и принимает задания на создание фото и видео

Служба связи передаёт изменения телефонам, обработчик получает файлы от модели

## Что подготовить перед запуском

- Для создания фото и видео нужны адрес запущенной службы Кандинского и закрытый ключ доступа к ней. Проверочный запуск останавливается, если подключение не прошло.
- Для регистрации и восстановления пароля нужны настройки SMTP и отдельный секрет для кодов. Без них сервер может запуститься, но запрос кода по почте вернёт ошибку.

Бери свои данные доступа и храни их в местном файле **.env** или в настройках окружения. В репозиторий добавляй только [пример с именами настроек](.env.example).

## Запуск для проверки

Установи и запусти Docker с Compose. Понадобятся адрес и закрытый ключ запущенной службы генерации Кандинского. Скачай этот репозиторий и из его корня выполни одну команду

    ./tools/dev.sh

На Windows запусти команду из WSL с включённой поддержкой Docker.

Вставь адрес и ключ, когда команда их запросит. Для автоматического запуска их можно передать через **KANDINSKY_REVIEW_GPU_URL** и **KANDINSKY_REVIEW_GPU_TOKEN**. Ввод ключа скрыт. Он хранится в настройках запущенных контейнеров до остановки стенда этой командой.

Команда проверит доступ к службе генерации и версии моделей. Затем она создаст местные настройки, поднимет PostgreSQL, применит миграции и подготовит проверочный аккаунт. При первом запуске Docker скачает образы, зависимости и около 290 МБ материалов для чатов. Дождись появления почты и пароля в терминале.

- Открой [описание запросов](http://127.0.0.1:8098/docs). Запрос **POST /v1/auth/login** выдаст ключ входа для напечатанной почты и пароля. Вставь ключ в **Authorize** и выполни **GET /v1/threads**. В ответе будут Плотная медиалента и Длинная история.
- В **POST /v1/jobs** укажи номер чата в **thread_id**, описание в **prompt** и новый ключ запроса в заголовке **Idempotency-Key**. Для фото выбери модель **image**, для видео выбери **video**. Когда **GET /v1/jobs/{job_id}** покажет готовность, открой результат через **GET /v1/assets/{asset_id}**. Номер файла придёт в поле **output_id**.
- Для быстрой проверки открой [состояние сервера](http://127.0.0.1:8098/health) и [состояние службы связи](http://127.0.0.1:8449/health).

Изображения и видео создаёт настоящая модель Кандинского на подключённой видеокарте. База и хранилище принадлежат отдельному проекту Docker **kandinsky-review**. Как подготовить свою службу генерации, описано в [программе запуска на Modal](tools/modal_gpu.py) и [настройке исполнителя](backend/app/Services/Gpu/Runner/setup.sh).

Если вычислительная служба поддерживает увеличение разрешения видео, для проверки этого режима задай **KANDINSKY_REVIEW_VIDEO_SR=true** перед запуском.

Чтобы остановить стенд и сохранить чаты, выполни

    ./tools/dev.sh stop

Следующий запуск использует тот же пароль аккаунта и те же тома. Адрес и ключ генератора можно указать заново для новой аренды.

Проверочный аккаунт создаётся при запуске. Чтобы пройти регистрацию с настоящим письмом, используй запуск ниже.

## Запуск с регистрацией и почтой

Подготовь местные настройки из корня проекта

    python3 tools/configure.py

Команда создаёт файл **.env** и готовит отдельные пароли для PostgreSQL и серверных служб. Дополни этот файл настройками генератора и почты.

### Генерация фото и видео

| Настройка | Что указать |
| --- | --- |
| **STUDIO_PROVIDER** | **kandinsky** для настоящей модели |
| **STUDIO_GPU_URL** | Адрес запущенной службы Кандинского. Для удалённой службы используй HTTPS |
| **STUDIO_GPU_TOKEN** | Ключ, который выдал владелец службы генерации. Если поднимаешь свой исполнитель, задай ему тот же ключ в **GPU_TOKEN** |

Для своей службы создай случайный ключ длиной не менее 32 символов. Программа запуска на Modal читает **STUDIO_GPU_TOKEN** из местного **.env** и сама передаёт его исполнителю. Доступ к аккаунту Modal нужен тому, кто запускает аренду. Бэкенд получает адрес и ключ уже запущенной службы. [Запуск генератора](tools/modal_gpu.py)

### Почта для регистрации и восстановления

| Настройка | Что указать |
| --- | --- |
| **STUDIO_SMTP_HOST** | Адрес SMTP от почтового провайдера |
| **STUDIO_SMTP_PORT** и **STUDIO_SMTP_SECURITY** | Порт и способ защиты из настроек провайдера. Часто это **587** и **starttls** либо **465** и **tls** |
| **STUDIO_SMTP_FROM** | Адрес отправителя, с которого провайдер разрешает отправлять письма |
| **STUDIO_SMTP_USER** и **STUDIO_SMTP_PASSWORD** | Логин и пароль SMTP, если провайдер требует вход. Для провайдера с паролями приложений используй отдельный пароль приложения |
| **STUDIO_PASSWORD_RESET_SECRET** | Отдельный случайный секрет длиной не менее 32 символов. Сервер использует его для проверки кодов регистрации и восстановления |

Для каждого секрета, который создаёшь сам, выполни команду отдельно и сохрани результат в **.env**

    python3 -c 'import secrets; print(secrets.token_urlsafe(32))'

### Порядок запуска

После заполнения **.env** собери общий образ один раз, проверь подключение к генератору и подними службы

    docker compose build api &&
    docker compose run --rm --no-deps -T --entrypoint python worker - < tools/check_review_gpu.py &&
    docker compose up --no-build --wait --wait-timeout 900

Открой [описание запросов](http://127.0.0.1:8098/docs). Запрос **POST /v1/auth/register/request** отправляет код на указанную почту. Передай полученный код вместе с почтой и паролем в **POST /v1/auth/register**. Затем проверь вход через **POST /v1/auth/login** и создание файла через **POST /v1/jobs**.

Для остановки выполни **docker compose down**. Том базы сохранится.

## Карта проекта

Названия и распределение обязанностей папок в [backend/app](backend/app) следуют структуре [warehouse-api](https://github.com/KirillAbrams/warehouse-api/tree/110c94cde683703cdee1bc3bd68c9443446ad7fe/app). Сервер работает на Пайтоне и FastAPI.

| Папка или файл | За что отвечает |
| --- | --- |
| [bootstrap](backend/bootstrap) | Собирает основной сервер, службу связи с телефонами и модератор |
| [config](backend/config) | Читает настройки базы, почты, исполнителя и сеансов |
| [routes](backend/routes) | Связывает адреса с обработчиками основного сервера, мобильной связи и обмена между службами |
| [Console/Commands](backend/app/Console/Commands) | Содержит служебные команды для оператора |
| [Contracts](backend/app/Contracts) | Описывает, что умеет исполнитель генерации |
| [Enums](backend/app/Enums) | Задаёт допустимые причины жалоб и решения по ним |
| [Exceptions](backend/app/Exceptions) | Описывает ошибки исполнителя, модерации и удаления аккаунта |
| [Http](backend/app/Http) | Содержит обработчики, правила проверки запросов, формы ответов и ограничения размера запросов. В [Controllers](backend/app/Http/Controllers) обработчики лежат на одном уровне. Имена обработчиков для телефонов начинаются с mobile |
| [Jobs](backend/app/Jobs) | Запускает обработку генераций и доставляет отложенные удаления на вычислительную машину |
| [Models](backend/app/Models) | Описывает таблицы аккаунтов, чатов, заданий и файлов |
| [Policies](backend/app/Policies) | Проверяет владельца чата, задания и файла, а также доступность удалённых записей |
| [Providers](backend/app/Providers) | Выбирает исполнитель генерации при запуске |
| [Services](backend/app/Services) | Содержит работу с [аккаунтами](backend/app/Services/Accounts), [чатами](backend/app/Services/Chats), [генерацией](backend/app/Services/Generation), [файлами](backend/app/Services/Media) и [модерацией](backend/app/Services/Moderation) |
| [source_links.py](backend/app/Services/Media/source_links.py) | Связывает файлы с чатами и ставит в очередь удаление файлов, которые больше не нужны |

Чтобы разобрать создание картинки, начни с [адреса запроса](backend/routes/api.py). Затем открой [обработчик запроса](backend/app/Http/Controllers/generations_controller.py), [запись задания](backend/app/Services/Generation/submit_jobs.py) и [службу очереди](backend/app/Services/Generation/queue.py). [Рабочий процесс](backend/app/Jobs/worker.py) вызывает [службу обработки](backend/app/Services/Generation/process_generation.py), чтобы выполнить задание и сохранить результат. [Формат ответа](backend/app/Http/Resources/generation.py) задаёт поля, видимые клиенту.


### Как оформлен код сервера

Названия папок первого уровня повторяют эталон. Файлы и функции Пайтона названы строчными буквами с подчёркиваниями. У функций доступа, генерации, загрузки и работы с базой типы показывают, что функция принимает и возвращает. Короткое описание поясняет условия повтора, блокировки и сохранения данных там, где это важно. Ruff проверяет формат, порядок импортов, оформление описаний функций и лишние отключения правил.

## Проверки

Установи Пайтон **3.12**, инструменты **ffmpeg** и **ffprobe**, команды **initdb** и **pg_ctl**

Для временной базы запускай проверки под обычным пользователем

    cd backend
    python3.12 -m venv .venv
    source .venv/bin/activate
    python -m pip install -r requirements-dev.lock
    python -m pip install --no-deps -e .
    python -m pytest tests --cov=app --cov=bootstrap --cov=config --cov=routes --cov=database.seeders --cov-branch --cov-fail-under=100

Полный замер считает строки и ветки основного сервера, службы связи и обработчика видеокарты

Проверки используют временные базы и управляемые ответы исполнителя

## Материалы сервера

[Набор стартовых чатов](backend/database/seeders/sample_media) хранится в папке сервера

- [Состав стартовой истории](backend/database/seeders/sample_media/history.json.gz) задаёт сообщения, порядок и ссылки на оригиналы. По нему сервер собирает две истории для нового аккаунта, если это разрешено настройками.
- [Источники файлов](backend/database/seeders/sample_media/sources.json.gz) связывают сохранённые файлы с авторами и условиями использования. По этому списку можно проверить происхождение набора.
- [Контрольная сумма архива](backend/database/seeders/sample_media/archive.sha256) нужна установщику для сверки скачанного набора. При несовпадении он отвергает архив и не подменяет исходники в хранилище.
- [Отпечатки распространённых паролей](backend/app/Services/Accounts/common_passwords.sha256) читает проверка нового пароля. Если отпечаток совпал, сервер просит выбрать другой пароль.
